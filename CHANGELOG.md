- **Fount Engine** (`apps/fount/`): a dependency-free WebGL2 FPS engine designed so Claude authors a game entirely as text and the finished game runs with zero API calls. Includes a shadow-mapped renderer with procedural material generation, Quake-style swept-AABB brush collision with a Source-feel character controller, 16-particle verlet ragdolls that inherit the victim's momentum and the killing impulse, a declarative entity output/input system, procedural audio synthesis, an in-browser editor that round-trips with map JSON, and two playable demo maps.
- `fount-gamedev` skill: teaches the map format, entity library, IO system and custom-behaviour API for the Fount engine, with three task-split reference files.
- Installer: `./install.sh` (wrapping `tools/install.py`) installs, updates, lists and uninstalls skills into `~/.claude/skills` or a project directory. Tracks what it installed in a manifest so it never overwrites or deletes a skill directory it didn't create without `--force`. Stdlib only, no network calls.
- `apps/fount/run.sh` launcher: serves the engine and opens a browser.
- **In-game developer console** (`apps/fount/engine/console.js`): press `` ` `` for `noclip`, `god`, `give`, `teleport`, `where`, `spawn`, `ragdoll`, `killall`, `clearbodies`, `ent`, `fire`, `map`, `restart` and `pause`, plus cvars (`sensitivity`, `fov`, `gravity`, `speed`, `jump`, `timescale`, `maxbodies`, `showfps`), tab completion and history. `fire` drives the same IO system map JSON uses, so a connection can be tested before it is wired.
- **Multiplayer** (`apps/fount/server/`, `apps/fount/engine/net.js`, `apps/fount/serve.sh`): one Node process serves the game files and hosts the session on a single port, so a game repo deploys with `git clone && ./serve.sh` and nothing else. The RFC 6455 WebSocket server is written against the Node standard library — no `npm install`, no dependencies, matching the engine's zero-dependency rule. Remote players are interpolated ~100ms behind the newest snapshot to keep motion smooth at 20Hz. Kills produce ragdolls on every client. `GET /api/status` exposes name, map, players and uptime for a server browser or uptime check.
- **Server admin**: the terminal running the server is its admin console — `status`, `say`, `kick`, `ban`/`unban`/`bans`, `admin`/`unadmin`, `map`, `restart`, `quit`. A player granted `admin` runs the same commands in-game by prefixing chat with `/`. The trust model is stated plainly in the code and the README: clients report their own position and hits, so this is built for community servers, not ranked play.
- Client multiplayer commands in the console: `connect`, `disconnect`, `say`, `name`, `players`, `status`.
- **Server-side anticheat** (`apps/fount/server/anticheat.mjs`). The server now loads the map and runs the engine's own collision code, so it validates claims against the same geometry the client collides with rather than a second implementation that could drift. It owns health, damage, death, respawns and scoring outright — a client's self-reported health is read by nothing, so godmode and self-resurrection are not expressible in the protocol. Every hit must correspond to a shot the server accepted, must leave from where the server thinks the player is, must point where they say they are looking, must intersect the target rewound to what the shooter could see (lag compensation, capped), and must have line of sight through the map; the server then computes the damage itself from where the ray landed, so a claim of 9999 damage or of a head shot at the victim's feet changes nothing. Fire rate, ammo and range are enforced and the dead cannot shoot. Movement is checked by sweeping the player's box through the world between reported positions, allowing for stair step-up and corner clipping, and an impossible path is corrected rather than punished.
- Graduated enforcement: violations are weighted (shooting through a wall counts for far more than one fast tick), decay by half every 30 seconds, warn to the log and to admins, and kick only on a sustained pattern — because a single anomaly is more often a lag spike than a cheat.
- **Online top-down games** (`apps/fount/server/mmo.mjs`, `engine/netcode.js`, `engine/online.js`). A server-authoritative server for top-down / RPG games: clients send intents, the server simulates at 120 Hz and sends per-client delta snapshots at 30 Hz, and the client predicts and reconciles its own character. Entities have `server` and `client` halves (flat classes still work, and single player is unchanged). Maps are instanced (`shared`, `static`, `party`, `solo`) with portals and reconnect.
- **Accounts and persistence**: scrypt accounts, hashed session tokens, an HTTP API, characters saved through `actor.snapshot()` with versioning and a migration hook, an audited gold economy with a ledger and rollback, and sqlite, file or custom stores.
- **Interest management**: a spatial hash with hysteresis, filtered events and a per-client byte budget that defers rather than drops distant updates.
- **Social and combat**: parties with a frame that reaches members at any distance and shared XP, chat channels with rate limits, ignore, filter and report hooks, emotes, engine-drawn name plates, health bars and bubbles; threat tables and taunts, friendly-target abilities, PvP modes with non-lethal duels, group-size scaling, wipe reset, personal loot and a sidekick hook.
- **Operations**: an admin console and authenticated HTTP admin API, `/metrics`, JSON logs, scheduled backups with restore, graceful shutdown with a countdown, environment and file config, and `server/loadtest.mjs` (50 bots in one instance used about a fifth of the tick budget on a laptop).
- **Polish**: a shared world clock (day/night, seasons, tides) and `func_water`, a camera cut-away for top-down walls, ground decals, UV-scrolling materials, sprite palette swaps and paper-doll layers, a text-defined music sequencer, the title/login/play `game.flow` state machine, HUD state parity online, and `sprites.html`, a sprite-sheet preview page.
- New references in the `fount-gamedev` skill: `multiplayer.md`, `persistence.md` and `online-migration.md`. `tools/new_fount_game.py --update --editor` now also refreshes `sprites.html`.
- `--anticheat off|lenient|normal|strict`, `--cheats` and `--verbose` server flags, plus an `anticheat` admin command that lists flagged players and changes the level live. `status` now shows each player's ping and marks anyone over the warning threshold.
- Cheat console commands (`noclip`, `god`, `give`, `teleport`, `spawn` and the `gravity`/`speed`/`jump`/`timescale` cvars) are disabled on a server that has not enabled them — protective as much as fair, since the anticheat cannot tell an honest player's noclip from a cheat client's.
- `apps/fount/server/anticheat.test.mjs`: a hostile client that speaks the wire protocol directly and asserts 17 cases, from phantom hits and wallhack shots to teleports and self-reported godmode — including that a legitimate shot still lands and an honest player is never touched. Zero dependencies (Node 21+ has a WebSocket client built in) and it starts and stops its own server.
- Round-trip latency is measured from the WebSocket keepalive rather than reported by the client, which is what sizes each player's lag-compensation window without trusting a number a cheat would inflate.
- Keyboard fire (`F`, `Enter`, `Ctrl`) and arrow-key look, so the whole game is playable without a mouse.

- `tools/new_fount_game.py`: scaffolds a Fount game as its own standalone repository — engine and multiplayer server vendored in, starter level, shell, editor, `run.sh`, `serve.sh`, README, MIT licence, and a git repo with a first commit. It also installs the `fount-gamedev` skill at the project's own `.claude/skills/`, so a Claude Code session opened on that repo knows the map format with SuperClaude nowhere present. `--vendor-only` adds Fount to an existing repo; `--update` refreshes the vendored engine, server and skill without touching the game's own content. Local only — it prints the git remote steps rather than pushing anything.

### Changed

- The repository is now `thatrgbgamer/SuperClaude-FountEngine`; clone URLs, the plugin marketplace reference and the plugin `homepage` point at the canonical name rather than relying on GitHub's rename redirect.
- The editor's `MAPS` array now uses the same `{ file, label }` shape as `index.html`'s. They had drifted into two different shapes for the same concept, which meant adding a level was a subtly different edit in each file.

### Fixed

- **The camera could become impossible to turn, with no error and no way back.** Mouse look depended entirely on pointer lock, and a refused lock was completely silent: `requestPointerLock()`'s promise rejection was unhandled, there was no `pointerlockerror` listener, and nothing on screen said the mouse wasn't captured — so the game looked fine while the mouse did nothing. Look now has three independent routes: pointer lock, hold-and-drag, and arrow keys. A blocked capture is reported on screen and in the console instead of vanishing, and `play()` asks for the mouse while the click's activation is still fresh rather than after an `await`.
- **Ragdolls exploded across the level.** `solveCollisions` rewrote each particle's implied velocity *inside* the constraint iteration loop, so every constraint correction fed back in as fresh speed and compounded six times per step. Limbs reached 120 m/s and stretched 51m, drawing as screen-filling polygons that made it look like the camera was stuck. Collision is now a positional correction inside the loop, with friction and into-surface damping applied once afterward.
- **Every ragdoll impulse was twice its intended strength**: impulses converted force to a verlet offset with `1/60` while the simulation steps at `1/120`. Both now share one exported `STEP_DT`.
- **Ramps with `dir: 1` produced a completely empty brush.** The cut plane's normal did not follow the sign of the run, inverting the halfspace. In `dm_crucible` this meant the ramp to the raised platform did not exist, leaving the platform, its NPC and its medkit unreachable.
- **`wedge` brushes never cut anything** — the diagonal plane passed through the corner it was meant to remove, so every wedge rendered as a plain box.
- Added hard safety rails to the ragdoll solver (45 m/s per particle, 2m reach from the pelvis, non-finite recovery) so no solver misbehaviour can draw a limb across the map again.
- `drawSegment` now rejects non-finite endpoints instead of rasterising them as a screen-filling triangle.
- Respawning no longer snaps the camera back to the spawn yaw, which read as the game fighting you for the mouse.
- **Movement was janky because the loop threw simulated time away.** The fixed-timestep accumulator capped substeps at a number lower than the frame-time clamp allowed, so a slow frame simulated less time than had really elapsed and discarded the remainder — 73 of 106 frames in a measured run. The cap is now derived from the clamp, and rendering interpolates between the previous and current physics state (players, ragdolls and props alike) instead of snapping to the latest step.
- **Shooting was mouse-only.** There was no keyboard fire binding at all, so anyone without a working mouse button could move and look but never shoot.
- **A class's own input handler was shadowed by the universal ones.** `Kill`, `Enable`, `Disable` and `Toggle` were handled before the entity's own definition got a look, so `killall` removed NPCs outright instead of letting them die and ragdoll. Class handlers now win, with the universal behaviour as the fallback it was meant to be.
- **The server's admin terminal was dead under every process manager.** Its stdin console was gated on `isTTY`, which is false whenever stdin is a pipe — i.e. under Docker, systemd and most supervisors — so the admin commands existed but could not be reached. It now attaches whenever stdin is readable.
- **The server defaulted to a map that only the demo has.** A scaffolded game has its own levels and no `dm_crucible`, so every joining client would have been handed a 404. The starting map is now resolved against what is actually in `game/maps/`, an explicitly requested map that is missing is a clear startup error rather than a silent one, and the `map` admin command refuses a path that does not exist instead of emptying the server on a typo.
- **The server broke outright inside a repo with a CommonJS `package.json`.** Node parsed `server.js` as CommonJS and died on the first `import`. The server modules are now `.mjs`, which is unambiguous regardless of what `package.json` a game repo keeps next to them.
- Two regexes in the server contained literal control bytes rather than escapes, which made git treat the file as binary and broke diffing and grep on it.
- **Any client could kill any player instantly, from anywhere.** The `hit` message named its own target and its own damage, and the server applied both without checking that a shot had been fired, that the target was reachable, or that anything was in the way. It also let a client set its own health, to 1000 if it liked. Both are now server-owned; see the anticheat entry above.
- The server checked shot origins against an eye height of 0.62 while the client's camera sits at 0.72, so its idea of where a player's eyes were had a permanent 10cm error.
- A single missed WebSocket pong disconnected a client. The keepalive now also measures latency, so it pings more often, and tolerating one missed pong at that rate would have dropped anyone with a brief lag spike; it takes several misses now.
- NPC and explosion damage never reached the server once health became server-owned, because NPCs are simulated per-client. Clients now report damage they inflict on themselves, which is safe to trust in a way reporting damage to others is not: the only thing a liar can buy is their own death.
